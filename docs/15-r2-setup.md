# Cloudflare R2 Setup Guide for Work Sample Uploads

This guide walks you through setting up Cloudflare R2 for storing work sample files (photos, documents) attached to log entries.

## Overview

- **Cloudflare R2** is S3-compatible object storage
- **Free tier**: 10GB storage, 1M Class A operations, 10M Class B operations/month
- **Paid tier**: $0.015/GB storage, minimal per-operation costs
- Files are organized by `familyId` for access control isolation

## Step 1: Create R2 Bucket

1. Log in to [Cloudflare Dashboard](https://dash.cloudflare.com)
2. Navigate to **R2 Object Storage** in the left sidebar
3. Click **Create bucket**
4. Enter bucket name: `hsmlogs` (or your preferred name)
5. Select your preferred location (Auto is fine)
6. Click **Create bucket**

## Step 2: Generate API Tokens

### Option A: R2 API Token (Recommended for Server-Side)

1. In Cloudflare Dashboard, go to **R2 Object Storage**
2. Click **Manage R2 API Tokens** (top right)
3. Click **Create API Token**
4. Configure:
   - **Token name**: `homeschool-keeper-backend`
   - **Permissions**: Object Read & Write
   - **Specify bucket(s)**: Select `hsmlogs`
   - **TTL**: No expiration (or set as needed)
5. Click **Create API Token**
6. **IMPORTANT**: Copy and save these values immediately:
   - `Access Key ID` → `R2_ACCESS_KEY_ID`
   - `Secret Access Key` → `R2_SECRET_ACCESS_KEY`

### Get Your Account ID

1. In Cloudflare Dashboard, look at the URL or go to **Overview**
2. Your Account ID is in the URL: `https://dash.cloudflare.com/<ACCOUNT_ID>`
3. Copy this → `R2_ACCOUNT_ID`

## Step 3: Configure CORS (for Direct Browser Uploads)

1. Go to **R2 Object Storage** → **hsmlogs** bucket
2. Click **Settings** tab
3. Scroll to **CORS Policy**
4. Click **Add CORS policy** and add:

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:5173",
      "http://localhost:8080",
      "https://your-production-domain.com"
    ],
    "AllowedMethods": [
      "GET",
      "PUT",
      "POST",
      "DELETE",
      "HEAD"
    ],
    "AllowedHeaders": [
      "*"
    ],
    "ExposeHeaders": [
      "ETag",
      "Content-Length",
      "Content-Type"
    ],
    "MaxAgeSeconds": 3600
  }
]
```

5. Click **Save**

## Step 4: Update Environment Variables

Add these to your `.env` file:

```dotenv
# Cloudflare R2 Storage
R2_ACCOUNT_ID=your-cloudflare-account-id
R2_ACCESS_KEY_ID=your-r2-access-key-id
R2_SECRET_ACCESS_KEY=your-r2-secret-access-key
R2_BUCKET_NAME=hsmlogs
R2_PUBLIC_URL=https://hsmlogs.<account-id>.r2.cloudflarestorage.com

# Optional: Custom domain for R2 (if configured)
# R2_CUSTOM_DOMAIN=https://files.yourdomain.com
```

### Finding Your R2 Endpoint URL

Your R2 S3-compatible endpoint URL format is:
```
https://<ACCOUNT_ID>.r2.cloudflarestorage.com
```

## Step 5: File Organization Structure

Files are stored with this path structure for security:
```
hsmlogs/
├── families/
│   ├── {familyId}/
│   │   ├── work-samples/
│   │   │   ├── {logEntryId}/
│   │   │   │   ├── {uuid}-{filename}
│   │   │   │   └── {uuid}-{filename}
│   │   │   └── ...
│   │   └── exports/
│   │       └── {timestamp}-report.pdf
│   └── ...
└── ...
```

This structure ensures:
- **Family isolation**: Each family's files are in their own folder
- **Log association**: Files are grouped by log entry
- **UUID prefix**: Prevents filename collisions

## Security Model

### Pre-signed URLs
- All file access uses **pre-signed URLs** generated by the backend
- URLs expire after a configurable time (default: 1 hour for downloads, 5 minutes for uploads)
- No public bucket access - all requests require valid signatures

### Family Isolation
- Backend verifies `familyId` before generating pre-signed URLs
- File paths include `familyId` - cannot access other families' files
- Upload paths are validated server-side

### Premium Feature Gating
- `uploadsEnabled` flag on Family model controls access
- Free tier: No uploads
- Paid tier: Uploads enabled
- Backend checks this before generating upload URLs

## Troubleshooting

### "Access Denied" errors
- Verify API token has read/write permissions for the bucket
- Check bucket name matches exactly
- Ensure CORS is configured for your origin

### CORS errors in browser
- Add your development/production URLs to CORS AllowedOrigins
- Make sure to include the protocol (http/https)

### Files not found
- Check the full path including familyId
- Verify the file was uploaded successfully
- Check expiration of pre-signed URLs
